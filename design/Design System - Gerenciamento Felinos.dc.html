Gerenciamento Felinos

01 — Personalidade

Clínico, calmo e rápido de usar entre um atendimento e outro

O sistema é um prontuário: o usuário digita muito, lê muito e consulta histórico sob pressão de tempo, em pé, no celular, dentro da clínica de outra pessoa. A identidade privilegia legibilidade densa, hierarquia previsível e ausência total de ruído decorativo. Nada de ilustração de pet shop — o tom é de instrumento profissional de saúde, com um resto de calor humano no acento.

Sentimentos-alvo
Confiança clínica · Calma · Controle · Precisão · Portabilidade. O oposto de: infantil, lúdico, promocional, denso demais.
Público-alvo
Veterinário autônomo felino, 28–50 anos, alta alfabetização digital, uso solo, 80% mobile em ambiente clínico com iluminação variável e mãos ocupadas.
Referências
Rigor tipográfico e densidade de Linear; clareza de formulário e semântica de erro de Stripe; neutralidade quente e leitura longa de Notion.
PRINCÍPIO 01
O dado clínico é o herói
Peso, data, diagnóstico e prescrição têm mais contraste que qualquer chrome de interface.
PRINCÍPIO 02
Uma cor de ação só
Teal = ação primária. Se tudo é destaque, nada é. Semânticas só comunicam estado, nunca marca.
PRINCÍPIO 03
Toque antes de mouse
Alvos ≥ 44px, campos ≥ 48px de altura, nada que dependa de hover para ser descoberto.
PRINCÍPIO 04
Destruição é rara e explícita
Excluir paciente cascateia atendimentos (API). Vermelho é reservado a isso e a erros reais.
Como o domínio da API moldou a identidade
Appointment
6 campos de texto longo por atendimento → tipografia de leitura longa e largura de medida controlada (≤ 75ch).
location_type
3 estados mutuamente exclusivos que revelam campos → padrão de Radio/Segmented, não Select.
weight_kg
Decimal(5,2) comparado ao longo do tempo → mono tabular obrigatório em números.
Problem 422
Erros por campo (RFC 7807) → estado de erro no input precisa de slot de mensagem nativo.
409 Conflict
Excluir tutor/local bloqueado por vínculo → variante Alert warning explicativa, não erro.
photo_url nullable
Foto some em redeploy (ADR-007) → avatar com fallback de iniciais é estado de primeira classe.

04 — Tipografia

Plus Jakarta Sans + JetBrains Mono

Plus Jakarta Sans para toda a interface: geométrica com terminais abertos, acentuação latina completa e desenhada para pt-BR (ç, ã, õ, á) — legível em 14px numa tela de celular sob luz de clínica, e com personalidade suficiente para não parecer template. JetBrains Mono para todo dado clínico e técnico: peso, datas, IDs, telefone, códigos de erro. Números tabulares alinham colunas na timeline e evitam leitura errada de dose.

08 — Componentes base

Especificação de estilo e regra de uso

Contratos de estilo — geometria, tokens e quando cada variante se aplica no domínio do produto. Nenhum layout de tela é definido aqui.

Alturas: sm 36 · md 44 (padrão) · lg 52. Padding horizontal 16/20/24. Radius md. Tipografia type.button. Transição 140ms ease-out em background e box-shadow — nunca em tamanho. Ícone opcional 18px à esquerda, gap 8.

Icon-only / FAB
44×44 · radius full · aria-label obrigatório
FAB "novo atendimento" fixo no mobile, bottom-right, shadow.lg.
Estados obrigatórios em todas as variantes: default · hover · active · focus-visible (shadow.focus) · disabled (bg disabled, texto disabled, cursor not-allowed) · loading (spinner 16px substitui o ícone, largura travada, texto mantido).
Input · Textarea
Altura 48 (44 no desktop), padding 12/14, radius md, border 1px secondary.200, bg surface, texto type.body 16px (evita zoom no iOS). Focus: border primary.500 + shadow.focus. Erro: border error.600 + mensagem error.700 em type.small, ligada por aria-describedby.
Anatomia: Label (type.label) → campo → helper/erro. Label sempre visível, nunca só placeholder. Campo opcional recebe sufixo "(opcional)" — a API tem muitos nullable, marcar o opcional é mais honesto que marcar o obrigatório.
Variantes: texto · numérico (mono tabular, sufixo "kg") · data · telefone (máscara) · senha (toggle de visibilidade) · busca (ícone + limpar) · textarea auto-grow de 3 a 12 linhas para os campos longos do atendimento.
Select
Mesma geometria do input + chevron 18px à direita. Menu com radius lg, shadow.md, item de 40px, item selecionado com bg primary.50 e check.
Select simples para listas fechadas e curtas (sexo do paciente). Combobox com busca obrigatório quando a lista vem paginada da API (tutor, local) — a partir de ~8 itens, digitar é mais rápido que rolar. Segmented control em vez de select quando há 2–3 opções que alteram o formulário — é o caso de location_type.
Checkbox · Radio · Switch
Checkbox 20×20, radius xs, borda secondary.300, marcado = primary.600 com check branco; estado indeterminado para "selecionar todos". Use para múltipla escolha e consentimentos.
Radio 20×20 circular, ponto interno 8px primary.600. Use para escolha única entre 2–5 opções sempre visíveis — sexo do paciente, tipo de local.
Switch 44×26, knob 22, off = secondary.300, on = primary.600, transição 160ms. Só para preferências de efeito imediato (tema escuro, manter conectado). Nunca dentro de formulário que exige salvar.
Área clicável dos três se estende ao label inteiro, com no mínimo 44px de altura.
Badge
Altura 22, padding 4/8, radius xs, type.caption 600. Fundo tonal 50/100 + texto 700 da mesma escala — nunca fill saturado com texto branco em tamanho pequeno.

Alert
Radius lg, padding 16, bg escala 50, borda 1px escala 200, ícone 20px na cor 600, título type.h6, corpo type.small. Sempre com texto explicativo — cor nunca carrega o significado sozinha.
info contexto e dicas · success confirmação inline após 201/204 · warning 409 Conflict (tutor com pacientes, local em uso) · error falha de rede, 401 expirado, resumo de 422 no topo do formulário. Toast é reservado a confirmações efêmeras; erro que exige ação fica inline.
Modal · Bottom sheet
Desktop: largura sm 420 / md 560 / lg 720, radius xl, shadow.xl, padding 24, overlay 55%. Mobile (< md): vira bottom sheet, radius 2xl no topo, altura máx 90vh, arrasto para fechar.
Foco preso no diálogo, Esc fecha, foco volta ao gatilho. Confirmação destrutiva descreve a consequência real ("Excluir Mimi apaga também os 12 atendimentos registrados") e exige clique no botão destrutivo — sem digitação de nome, que é fricção desproporcional para uso solo.
Tooltip
bg secondary.900, texto #FFFFFF type.caption, padding 6/10, radius sm, shadow.md, delay 300ms, offset 8. Máximo 2 linhas.
Só para revelar o nome de um botão icon-only ou expandir uma abreviação. Nunca guarda informação essencial — no mobile (80% do uso) hover não existe; a alternativa é helper text visível.
Card
bg card, border 1px, radius lg, padding 20 (16 no mobile), shadow.xs. Clicável ganha hover bg + shadow.sm e é um elemento focável único.
Estático agrupa dados (ficha do tutor) · clicável é item de lista (paciente) · timeline tem barra de 3px accent.500 à esquerda e data em mono no topo. Máximo um nível de card dentro de card.
Table
Cabeçalho bg secondary.50, type.label, sticky. Linha 52px, divider entre linhas, hover bg hover, zebra desligada. Números em mono tabular alinhados à direita; datas em mono à esquerda.
Abaixo de md, tabela vira lista de cards — não há scroll horizontal. Paginação offset (a API expõe page · per_page · total · total_pages) fica no rodapé com o total à esquerda. Skeleton de 5 linhas no carregamento; estado vazio com uma ação primária.
Tabs
Underline de 2px primary.600 no item ativo, texto secondary.600 → secondary.900 quando ativo, altura 44, gap 24. Variante "pill" (bg primary.50, radius full) só dentro de card.
Máximo 4 abas, rolagem horizontal no mobile, seta esquerda/direita navega. Use para facetas do mesmo recurso (Atendimentos · Dados · Tutor na ficha do paciente); nunca para etapas sequenciais.
09 — Ícones

Lucide, traço 1.75px

Por que Lucide
Grade de 24px com traço uniforme que combina com o peso 500/600 da Plus Jakarta Sans; licença ISC sem restrição comercial; pacote lucide-react é tree-shakeable, o que importa num PWA que precisa carregar rápido em 4G de clínica; e tem cobertura nativa do vocabulário do domínio — cat, syringe, stethoscope, pill, weight, calendar, map-pin, house, user-round.
Rejeitados: Heroicons (bom, porém vocabulário veterinário inexistente e duas famílias de peso que convidam à inconsistência); Material Symbols (linguagem visual do Android sobrepõe a marca); Phosphor (excelente, mas 6 pesos são liberdade demais para um sistema mantido por uma pessoa).
Regras de uso
Tamanhos: 16 · 18 · 20 · 24 (só estes)
Stroke: 1.75px fixo
Cor: herda currentColor
Alvo mínimo: 44×44 na área clicável
icon-only exige aria-label
Decorativo: aria-hidden="true"
Um ícone por conceito, para sempre. Um mapa conceito → ícone vive no código, não na cabeça de quem desenha.

11 — Tokens

Duas camadas: primitivo e semântico

Componentes consomem apenas tokens semânticos (color.action.primary.bg), nunca primitivos (colors.primary.600). É essa indireção que faz o dark theme funcionar sem um único if nos componentes. Como o projeto é Turborepo, o arquivo de tokens vive em packages/shared — mesma lógica dos DTOs.

Fonte única em JSON no packages/shared; build gera CSS custom properties e tipos TS.
Troca de tema
Só os semânticos são redefinidos em [data-theme="dark"]. Primitivos são imutáveis.
12 — Acessibilidade

WCAG 2.2 AA como piso

Todo par texto/fundo do sistema foi medido. Texto corrido atinge AAA (≥ 7:1); nenhum par de interface fica abaixo de 4.5:1, exceto estados desabilitados, que a norma isenta.

Proibições fixas: nunca usar o degrau 500 de nenhuma escala como texto sobre fundo claro; nunca texto branco sobre warning; nunca borda mais clara que o degrau 200 como único delimitador de campo (3:1 mínimo em elementos de UI).
Foco e teclado
Anel de 3px com 2px de offset via :focus-visible — visível sobre qualquer superfície, jamais removido com outline:none. Ordem de tabulação segue a ordem visual. Skip link para o conteúdo principal. Modal prende o foco e o devolve ao gatilho. Atalhos: / foca a busca, Esc fecha camadas, ⌘↵ salva formulário.
Tamanhos e alvos
Alvo mínimo 44×44 (WCAG 2.2 SC 2.5.8 pede 24; adotamos 44 por uso com uma mão). Texto nunca abaixo de 12px, corpo em 16px. Layout íntegro até 200% de zoom sem scroll horizontal. Respeita prefers-reduced-motion desligando transições não essenciais.
Semântica e erros
Erros 422 por campo ligados por aria-describedby + aria-invalid, com resumo em role="alert" no topo. Toasts em aria-live="polite". Estado nunca comunicado só por cor: sempre ícone ou texto junto. Idioma lang="pt-BR" para leitores de tela.
13 — Justificativas

Decisões e o porquê de cada uma

No mesmo formato dos ADRs da arquitetura: contexto, decisão, consequência. Serve de defesa contra mudanças por gosto pessoal daqui a seis meses.

DDR-001
Teal como cor de marca
Saúde pede azul-verde; azul puro é genérico de SaaS e verde puro colide com o feedback de sucesso. O teal fica distante o suficiente do verde de sucesso (Δhue ≈ 35°) para não confundir, mantém percepção de assepsia e, em oposição ao terracota do acento, gera uma paleta quente/fria equilibrada sem gradiente decorativo. Efeito na UX: a ação primária é reconhecível em 100ms em qualquer tela, porque nenhuma outra coisa é teal.
DDR-002
Uma escala neutra só
Sistemas mantidos por uma pessoa apodrecem quando têm "gray" e "slate" e "secondary" fazendo a mesma coisa. Fundindo neutro e secundário numa escala azulada, todo cinza da interface tem a mesma temperatura da marca. Efeito: menos decisões por tela e zero deriva de tom entre módulos.
DDR-003
Mono obrigatório em dado clínico
O campo weight_kg é Decimal(5,2) comparado entre atendimentos — é o principal indicador de evolução de um felino. Números tabulares alinham a vírgula na vertical e tornam a variação legível de relance. Datas ISO e telefones ganham o mesmo tratamento. Efeito: reduz erro de leitura de dose e peso, que é risco clínico real.
DDR-004
Corpo em 16px e alvos de 44px
O uso é predominantemente mobile, dentro da clínica de terceiros, muitas vezes com uma das mãos ocupada segurando o animal. Abaixo de 16px o iOS aplica zoom automático ao focar um input, quebrando o layout. Efeito: formulário longo de atendimento preenchível sem zoom e sem toque errado.
DDR-005
Semântica alinhada aos códigos HTTP
A API já classifica o mundo: 201/204 sucesso, 409 conflito, 422 validação, 401 sessão. Amarrar cada cor semântica a um código elimina discussão caso a caso e garante que o mesmo evento sempre pareça igual. Especialmente 409 como warning, não erro — o usuário não errou, existe um vínculo a resolver. Efeito: mensagens previsíveis e front-end trivial de implementar.
DDR-006
Dark theme desde o dia zero
Atendimento domiciliar e emergência noturna são parte do trabalho descrito na arquitetura. Retrofitar tema escuro depois exige revisar todos os componentes. Com dois conjuntos de tokens semânticos desde o começo, o custo é próximo de zero. Efeito: conforto visual em ambiente escuro e economia de bateria em OLED.
DDR-007
Escopo enxuto de componentes
Treze componentes cobrem os 27 endpoints do MVP. O princípio "simplicidade primeiro" da arquitetura vale para o design: nada de data-grid, wizard ou date-range picker antes de existir tela que precise. Efeito: sistema que uma pessoa consegue manter, com bundle pequeno para o PWA.
DDR-008
Acento terracota fora das ações
O produto precisa de algum calor — trata de animais e de vínculo com tutores — mas calor não pode virar ruído num prontuário. Restringir o terracota a avatar sem foto, marcador de timeline e estado vazio dá identidade sem competir com o teal. Efeito: o sistema parece humano sem parecer app de pet shop.
